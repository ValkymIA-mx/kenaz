# M0 KEY: Linux transport investigation

**D7 is pending hardware acceptance.** `spikes/key` pins `yubikit = "=1.0.0-beta.0"` and builds on the Linux x86-64 host with Rust 1.99, libpcsclite 2.5.3 and libudev 262. No personal key is modified. This is a standalone spike, not the M1 `KeyPort` implementation.

## Observed

```sh
cargo run --locked --manifest-path spikes/key/Cargo.toml
```

Output: `PC/SC readers=0`, `FIDO HID devices=0`, `OTP HID devices=0`; exit **2**, explicitly meaning no key discovered, not hardware success. Independent `lsusb -d 1050:` returned exit 1 and `ykman list` returned no keys. The socket unit was active and the service initially inactive (socket activation is not a service failure).

A process-local inaccessible PC/SC endpoint exercises the real library error without stopping the user's service:

```sh
PCSCLITE_CSOCK_NAME=/nonexistent/kenaz-m0-pcsc.sock spikes/key/target/debug/kenaz-key-spike
```

Output: `Pcsc(NoService) (PC/SC error: The Smart card resource manager is not running)`; HID enumeration still completes; exit **1**. This is an unreachable-socket experiment, **not** a measurement with the real daemon stopped. It establishes the error to preserve, not the distro's installation or permission behavior.

## Source findings affecting D7

The pinned [PC/SC implementation](https://docs.rs/crate/yubikit/1.0.0-beta.0/source/src/platform/pcsc.rs) has important behavior beyond the protocol API:

- `PcscSmartCardConnection::open` retries exclusive/shared access and, if shared access fails, calls `kill_pcsc_blockers`. On Unix this can run `pkill -9 scdaemon` or send SIGHUP to `yubikey-agent`, without an application confirmation. `YKMAN_NO_EXLUSIVE` skips the exclusive attempt but **does not disable killing**.
- `PcscSmartCardConnection::new(reader, false)` opens directly in shared mode and preserves the typed error; it does not run that automatic recovery. `PcscError::is_sharing_violation` identifies a sharing violation, but does not identify which process holds the card.
- The [high-level discovery implementation](https://docs.rs/crate/yubikit/1.0.0-beta.0/source/src/platform/device.rs) discards initial PC/SC/HID enumeration errors through `if let Ok(...)`; `LocalYubiKeyDevice::open_smartcard` also maps a sharing violation to `CcidUnavailable`. A zero-device result alone cannot distinguish absence, permission failure and a stopped service.

The spike therefore enumerates each transport separately and uses direct shared connections. `--probe` additionally reads model, serial, firmware, form factor, USB/NFC capabilities and enabled applets over a Yubico USB reader, lists the OATH credential count without logging labels, and reads CTAP2 `getInfo` over HID. This optional hardware path is compiled but **not run on a key**. It does not try PINs or calculate existing credentials (HOTP calculation can advance a counter).

## Remaining hardware gate and fallback trigger

Use dedicated project keys only: two current-firmware YubiKey 5 and a Security Key. In LX1/LX2 record normal-user HID access and the actual daemon-stopped case. Run OATH list plus TOTP calculation against a locally generated fixture; authenticated stored-passkey listing; PIV key/certificate import and verified signature in 9c (including the owner's e.firma fixture); OpenPGP import; OTP configuration read and reversible slot swap. Do not put private keys, PINs or e.firma inputs in this repository. Obtain explicit approval before writing or swapping physical keys.

Reproduce the actual GnuPG contention case before accepting a detection or repair: preserve the sharing error, explain that another program may hold the card, and offer the owner's `gpgconf --kill scdaemon` only with consent. A process name or sharing violation alone is not a reliable attribution to GnuPG. Do not use the library's forced termination as the fix.

**Proposed D7 gate:** retain the pinned protocol library if every required operation and error can be exercised through non-destructive, error-preserving transport entry points. The source findings above do not yet force the full fallback because direct connection APIs exist. Trigger an upstream fix/local adapter change for a reproducible transport defect; trigger the documented `ctap-hid-fido2` + `pcsc` fallback if a required operation cannot be implemented or a safety/correctness gap cannot be isolated behind the adapter. Decide go/no-go only after the real matrix and D1 interoperability runs; no successful applet, contention, permission or e.firma result is claimed here.
