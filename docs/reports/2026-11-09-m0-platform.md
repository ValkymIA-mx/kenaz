## Window experiment

Slint and its build crate are pinned to 1.18.1, with the winit Wayland backend, software renderer and accessibility feature; default features are disabled, so the X11 backend is not selected. The Spanish `.po` catalog is compiled into the binary with Slint's bundled translation support. English is the source language; the button selects Spanish and English through Slint's translation API rather than a Rust string dictionary. The single button also alternates the simulated touch message so the live region changes. The line edit and button have an explicit blue outline when their `has-focus` property is true; the line edit has an accessible label and the message requests a polite live region. These are implementation choices to inspect, not proof of Orca behavior.

On a host with Rust, required Wayland/font libraries and a working Wayland session, from the repository root:

```sh
cargo build --manifest-path spikes/ui/Cargo.toml
cargo run --manifest-path spikes/ui/Cargo.toml
```

For an automatic native-window capture without injecting desktop input:

```sh
cargo run --locked --manifest-path spikes/ui/Cargo.toml -- --capture
```

This writes `spikes/ui/target/captures/en.png` and `es.png`; both were visually inspected. The host session is KDE Wayland (not the required LX1/LX2 GNOME guests). The Spanish catalog also passed `msgfmt --check-format`. Focus outlines compile but were not exercised by keyboard input; screenshot capture is Slint's window snapshot API, **not** the desktop screenshot portal.

Use Tab/Shift+Tab to move between the text field and button; type in the field and activate the button with Space or Enter. Check the visible focus outline, English/Spanish text, and changing message. This native build is **host-only**, not a guest-compatible artifact. If the shell lacks a working Wayland session, launch from within one rather than falling back to X11. The catalog is a gettext-format `.po` bundled by Slint; runtime `msgfmt`/`.mo` files are not required for this experiment. Source language text is English; no English `.po` is required.
