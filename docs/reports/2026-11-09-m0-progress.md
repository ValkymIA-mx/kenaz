## Open exit gates

- **D1:** implement actual plugin-compatible PIV/FIDO formats and card operations, then prove both directions with the real age plugins. The custom age software stanza is not that proof.
- **D2:** choose shipped unlock options and recommendation only after the hardware/plugin/guest matrix, with Windows elevation still unknown until M5.
- **D3/D4:** import the candidates onto test keys; prove GnuPG/Thunderbird and SSH acceptance. Software certificate verification alone does not decide these.
- **D7:** exercise every specified applet, e.firma signature, user permissions and actual GnuPG contention before deciding YubiKit go/no-go.
- **Platform/D14 input:** provision LX1/LX2, USB redirection and clean snapshots; baseline-container builds, ARM64 cross-build/run, Wayland screenshot portal QR, Orca, keyboard navigation and 125%/150% scaling remain unrun.
- **U0:** recruit about five intended users across es/en, run the paper prototype, fix and re-check blocking issues, then agree the M1 screen wording/map.

No Yubico device was detected. The system libvirt connection failed because the `virtqemud` socket is missing; required guest inventory could not be verified. No host packages were installed, privileged services changed, physical keys written, or participant findings invented. A working host KDE Wayland session was found through the shell despite stripped environment variables in the evaluation subprocess.

**Next executable gate:** make the dedicated project keys and LX1/LX2 lab available, then run KEY and D1 compatibility checks before choosing D2/D7. U0 recruitment can happen independently. Do not start M1 as though M0 had passed.
